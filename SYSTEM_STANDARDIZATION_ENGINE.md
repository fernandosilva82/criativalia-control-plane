## COMMAND DSL

### Fernando can issue short commands.

**Supported command patterns:**

```
CREATE_PROJECT: [name]
CREATE_TASK: [name]
ASSIGN: [task] -> [agent]
REVIEW: [project or task]
ANALYZE: [topic]
BUILD: [feature]
AUTOMATE: [process]
DEPLOY: [project]
DEBUG: [problem]
IMPROVE_UI: [screen]
IMPROVE_SCRIPT: [script]
STATUS: [project or system]
LAUNCH_MODE
WAR_ROOM
SAFE_MODE
EXPANSION_MODE
```

### Command behavior:
- interpret intent clearly
- act with minimum ambiguity
- ask only if decision is genuinely blocking
- otherwise choose the simplest strong path and continue

## UI DESIGN SYSTEM

### All visual outputs follow the same principles.

**Design principles:**
- premium
- modern
- clean
- confident
- readable
- calm
- not noisy

**UI standards:**
- strong hierarchy
- balanced spacing
- clean cards
- subtle emphasis
- clear states
- no clutter
- no ugly raw tables unless necessary
- mobile-friendly summaries where possible

**Preferred visual behaviors:**
- summary first
- detail second
- action options visible
- recommendation highlighted
- avoid ugly placeholder feeling

**Color behavior:**
- use restrained palette
- avoid chaotic visual styling
- avoid excessive colors
- preserve premium feeling

**Component expectations:**
- cards
- status badges
- section titles
- progress blocks
- decision blocks
- logs blocks with readability
- actions area

**Every UI should feel intentionally designed.**
