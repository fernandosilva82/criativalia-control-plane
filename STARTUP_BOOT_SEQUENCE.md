# CRIATIVALIA_STARTUP_BOOT_SEQUENCE — System Extension

## Purpose
Define how Criativalia boots, initializes context, loads memory, checks systems, and enters active runtime mode.

**The company must not start in a confused state. It must start clean, aware, and operational.**

---

## BOOT OBJECTIVE

On startup, the system must:
- [x] load core identity
- [x] load memory
- [x] load active projects
- [x] load known tools
- [x] inspect system health
- [x] inspect deployment readiness
- [x] inspect runtime readiness
- [x] detect blockers
- [x] define current focus
- [x] enter active operating mode

---

## BOOT PHASES

### Phase 1: Identity Load
- load company mission
- load Fernando preferences
- load agent registry
- load standards
- load operating rules

### Phase 2: Memory Load
- load agent memory
- load project memory
- load decision memory
- load tool memory
- load failure/success memory

### Phase 3: System Check
- inspect active projects
- inspect blocked projects
- inspect active tasks
- inspect recent failures
- inspect pending decisions

### Phase 4: Tooling Check
- inspect repository state
- inspect GitHub readiness
- inspect Vercel readiness
- inspect available scripts
- inspect runtime dependencies

### Phase 5: Operational Focus
- identify top priority work
- identify quick wins
- identify blockers
- identify safe autonomous tasks
- identify decisions requiring Fernando

### Phase 6: Enter Runtime
- activate runtime supervisor
- start heartbeat cycle
- monitor agents
- continue execution

---

## BOOT CHECKLIST

At startup, always check:
- [ ] what projects are active?
- [ ] what is blocked?
- [ ] what is ready for review?
- [ ] what is ready for deploy?
- [ ] what failed recently?
- [ ] what can be improved now?
- [ ] what decisions are pending?
- [ ] what safe work can continue immediately?

---

## BOOT PRIORITY RULE

After boot, prioritize in this order:

1. critical failures
2. blocked important projects
3. deploy issues
4. pending reviews
5. active project progress
6. automation opportunities
7. UX improvements
8. experiments

---

## BOOT REPORT RULE

After startup, create a short boot summary:

```
Startup Summary

System state: [stable / warning / blocked]
Active projects: [n]
Blocked items: [n]
Pending decisions: [n]

Top focus: [short]
Immediate recommendation: [short]
```

This summary should be clean and short.

---

## BOOT FAILURE RULE

If startup detects serious issues:
- activate SAFE_MODE or WAR_ROOM_MODE
- notify Fernando if needed
- focus on stabilization first
- postpone non-essential work

---

## BOOT CONTINUITY RULE

The system must not forget unfinished work.

If previous work exists:
- resume from last reliable state
- do not restart from zero
- preserve project continuity
- preserve deploy continuity
- preserve review continuity

---

## BOOT QUALITY RULE

Startup must be:
- clean
- predictable
- structured
- aware
- useful

**Never start in a noisy or random state.**

---

## FINAL RULE

**Criativalia startup must feel like a real company opening for work:**

aware of yesterday,  
clear on today,  
ready for action.
